# Honey Chain

Blockchain-backed honey traceability + smart beekeeping management. **100% software prototype** — no ESP32, Arduino, sensors, or physical hives. The IoT layer is a **Virtual IoT Hive Simulator**.

## Stack
TanStack Start (React 19) · TypeScript (strict) · Tailwind CSS v4 + shadcn/ui · Lucide · Recharts · Lovable Cloud (PostgreSQL + Auth, RLS enabled).

## Demo credentials
Open `/auth` → **Enter Demo Mode as Rajesh Patil** (creates/uses `rajesh.demo@honeychain.app` / `HoneyChain#2026`).

## Critical demo flow
1. Sign in (Demo Mode) → `/dashboard` overview: hives, health, AI alerts.
2. `/dashboard/hives` → open **H-102**.
3. **Start simulation** → live virtual telemetry; **Simulate Hive Stress** → readings shift, risk rises, AI alert fires and is stored.
4. Review AI Hive Intelligence (risk, factors, recommendation) and Productivity Prediction (harvest kg, window, confidence).
5. `/dashboard/batches` → **Create batch** (harvest event is anchored automatically).
6. Open the batch → add processing / quality-check / packaging events, add quality tests, download the QR.
7. Open `/verify/HC-2026-00124` (or your new code) → consumer page → **Verify blockchain record**.

## Architecture
- `src/lib/honey.ts` — virtual IoT simulator, explainable AI-assisted analysis, productivity prediction, blockchain abstraction (SHA-256 via Web Crypto).
- `src/lib/data.ts` — typed data access + event/proof recording + integrity verification.
- `src/routes/` — landing, auth, `_authenticated/dashboard/*` (overview, hives, batches, supply chain, analytics), public `verify/*`.

### On-chain vs off-chain
- **On-chain (proof only):** batch identifier, event type, timestamp, data hash, tx reference.
- **Off-chain:** users, sensor readings, images, analytics, full batch detail.

### Blockchain modes
Default is **Simulation Mode**, clearly labelled everywhere; proofs are real SHA-256 hashes stored off-chain and are never presented as real on-chain transactions. Setting `VITE_EVM_RPC_URL` and `VITE_HONEYCHAIN_CONTRACT` switches `anchorProof()` to the testnet path (signer wiring is the one remaining integration step).

## Environment variables
Backend variables (`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID`) are managed automatically by Lovable Cloud. Optional: `VITE_EVM_RPC_URL`, `VITE_HONEYCHAIN_CONTRACT`. No keys are hardcoded.

## Database
Tables: `profiles`, `user_roles`, `apiaries`, `hives`, `sensor_readings`, `ai_predictions`, `honey_batches`, `traceability_events`, `quality_tests`, `blockchain_records`. RLS is on everywhere: public read for traceability data (needed for QR verification), authenticated writes, owner-only deletes, private profiles and roles. Roles live in a separate `user_roles` table with a `has_role()` security-definer function. Demo data (Rajesh Patil, H-101…H-104, HC-2026-00124) is seeded by migration.

## Deployment
Publish from Lovable; the backend deploys with it. Local: `bun install && bun run dev`.

## Known limitations
- AI analysis is explainable rule/statistics-based decision support — **not** a validated veterinary or scientific bee-disease diagnosis.
- Blockchain runs in simulation mode until testnet credentials + a signer are configured.
- Sensor data is generated by the virtual simulator, not real hardware.
- Consumer verification is read-only and does not require an account.
